# Debug and fix

Triage labels each confirmed bug `bug` + `ready-for-agent-debugging`: the agents' debugging queue. This skill works one bug from that queue end to end. The debugging discipline lives in `diagnosing-bugs`; this skill wraps it with the tracker: claiming the bug, choosing where the fix goes, and leaving the issue with an outcome a person can act on.

Read the tracker doc, `docs/agents/triage-labels.md` for the label strings, and `docs/agents/team.md`. If they don't exist, tell the user to run `/setup-imick-skills`. Every comment starts with:

```
> *This was generated by AI while debugging.*
```

## Run

1. **Pick the bug.** `/debug-and-fix #42` is that issue. A bare `/debug-and-fix` takes the oldest open, unassigned issue labelled `ready-for-agent-debugging`. Skip anything already assigned: someone else has claimed it.

2. **Claim it** before any other work: assign it to yourself (`gh issue edit <n> --add-assignee @me`). Read the issue, its comments and the triage notes.

3. **Choose the branch.** If the issue sits under an epic, check out the epic's branch (named in the epic's body). Otherwise create `fix/<n>-<slug>` from the default branch.

4. **Diagnose.** Call the Skill tool with "diagnosing-bugs", handing it the report: the symptom, the reporter's steps, the triage notes. For a bug the user sees in the UI it reproduces in the browser first ([its BROWSER.md](../diagnosing-bugs/BROWSER.md)). Follow it through Phase 5 when the diagnosis is **clean**:
   - a red-capable loop reproduced the reporter's symptom, and the repro is minimised,
   - the winning hypothesis is proven, not just plausible,
   - a correct seam exists for the regression test.

   Anything short of clean stops before the fix: the outcome is a diagnosis for a person, not a guess shipped as a fix.

5. **Land the outcome**, then remove `ready-for-agent-debugging`:

   | Outcome | Labels | Assignee | Comment |
   | --- | --- | --- | --- |
   | **Fixed** | `bug` + `ready-for-review` | stays you | Root cause, evidence, the regression test, and the PR |
   | **Diagnosed, fix needs a person** (judgment call, no correct seam, risky change) | `bug` + `ready-for-human` | the area's default person | The full diagnosis: repro, evidence, proven cause, suggested fix, and why it stopped |
   | **Can't reproduce** | `needs-info` + `ready-for-human` (replacing `bug`) | the reporter if a collaborator, else the area's default person | What was tried (browser, accounts, variations) and specific questions for the reporter |
   | **Works as intended** | `wontfix` + `ready-for-human` (replacing `bug`) | the area's default person | Why, with evidence; a person confirms and closes it |

   **Fixed** means, by branch:
   - **`fix/` branch**: commit the regression test and the fix, push, and open a PR whose body says `Fixes #<n>` (call the Skill tool with "pr" for its shape). Merging the PR closes the issue.
   - **Epic branch**: commit there and push; there is no separate PR. The fix has landed, so close the issue with the comment, linking the commit.

   A reporter's reply to a `needs-info` comment re-runs triage, which puts the bug back in this queue when it's reproducible.

6. **Report** to the user: the outcome, the issue and PR by name with links, and the hypothesis that turned out correct.

## The comment

```markdown
> *This was generated by AI while debugging.*

## <Fixed | Diagnosed | Can't reproduce | Works as intended>

**Reproduction:** <browser or harness used; starting URL, account role, steps>
**Evidence:** <the symptom as observed: console errors, failing requests, wrong output; redacted>
**Loop:** `<the command that goes red on this bug>`
**Cause:** <the proven hypothesis, or the ranked ones still open>
**Fix:** <what changed and the regression test, with the PR or commit link; or the suggested fix and why it needs a person>
```

For **can't reproduce**, replace Cause and Fix with what was tried and the questions for the reporter, in the triage notes' "What we still need from you" form.
